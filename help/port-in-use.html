Another program is using the wiki’s port

Only one program can answer on a port. When DesktopWiki finds its port taken, it names the program that has it. Here’s how to free the port, or move the wiki to another one.

The quickest fix: pick another port

DesktopWiki works on any port from 1024 to 65535. 8090 is its usual one. Port 443 just leaves the port out of the address (https://your-pc/ instead of https://your-pc:8090/), so it’s nice to have but not needed.

  • In the wiki: Configuration › Who can open the wiki › Port.
  • From the tray: right-click the DesktopWiki icon, Configure, then Change port…
  • If the wiki couldn’t start at all, DesktopWiki asks for another port right away.

Bookmarks on other devices need the new address afterward. If the wiki has a desktopwiki.net name, phones and other PCs just keep using that name with the new port.

VMware Workstation (VMware Workstation Server, port 443)

VMware Workstation installs a service called VMware Workstation Server (vmware-hostd.exe). It starts with Windows and listens on port 443, even in versions that no longer have the Shared VMs feature it was made for. Your virtual machines don’t need it: they keep working without it. Only sharing VMs and connecting to this PC from another VMware Workstation use it.

To turn it off, open PowerShell as an administrator (right-click Start, then Terminal (Admin) or Windows PowerShell (Admin)) and run these two commands:

Stop-Service VMwareHostd
Set-Service VMwareHostd -StartupType Disabled

The first stops it now. The second keeps it from starting again with Windows. On VMware Workstation 16.1 and earlier you can do the same from VMware itself: Edit › Preferences › Shared VMs › Disable Sharing. There you can also change its port instead.

To turn it back on later:

Set-Service VMwareHostd -StartupType Automatic
Start-Service VMwareHostd

Windows’ own web server (HTTP.sys or IIS)

When DesktopWiki says Windows’ web server has the port, it’s usually IIS, Microsoft’s web server, which you or a program may have turned on. If you don’t run websites with IIS, stop its service in an administrator PowerShell:

Stop-Service W3SVC
Set-Service W3SVC -StartupType Disabled

If you do use IIS, give the wiki another port instead (see above).

Apache, nginx, XAMPP, Docker and other web servers

  • Apache or XAMPP: stop it from its control panel, or change the Listen line in httpd.conf (and httpd-ssl.conf for 443).
  • nginx or Caddy: stop it, or change the port in its configuration file.
  • Docker Desktop: a container is publishing the port (for example -p 443:443). Stop that container, or publish it on another port.

Finding the program yourself

DesktopWiki names the program when Windows tells it. To look yourself, run this in PowerShell, with the wiki’s port in place of 443:

Get-NetTCPConnection -LocalPort 443 -State Listen | ForEach-Object { Get-Process -Id $_.OwningProcess }

Process 4, named System, is Windows’ own web server (see above).

After freeing the port

Start the wiki again if it stopped: right-click the DesktopWiki icon in the tray, choose Configure, and click Start beside Runs. Restarting the PC works too. Then open the wiki’s address to check it’s the wiki that answers.

Why some programs used to share the port with the wiki

Windows lets two programs listen on one port when both ask for it, and then either one may get each visit. With VMware Workstation Server on 443, that meant https://your-pc/ could open VMware’s page instead of the wiki. DesktopWiki now claims its port for itself: it won’t start on a port another program holds, and it says which program has it, so nothing quietly takes the wiki’s visitors.
